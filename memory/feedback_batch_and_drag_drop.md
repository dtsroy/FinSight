---
name: 批量与拖拽上传偏好
description: 用户在文件类交互上偏好"支持一次多个 + 拖入即可" 的组合模式，不要只提供单文件+点击按钮的最小实现。
type: feedback
---

规则：涉及用户"上传/添加照片、文档、导入文件"的入口，默认同时提供以下两种便捷方式，不要只做单文件点击版本：
1. 一次可选/拖入多个文件（批量），处理进度分文件展示，最终结果可汇总核对。
2. 拖拽到入口区域（不只是按钮上）也能直接触发上传。

Why: 用户在「财务 X 光」的截图 OCR 场景明确要求 "批量加截图 + 拖动照片到那个按钮也可以传"，说明他对文件类操作的默认期待就是批量 + 拖拽，认为单文件+按钮的最小实现是缺功能。

How to apply:
- 下一次遇到"上传截图/图片/CSV/PDF" 类需求时，直接把批量 + 拖拽当作出厂标准，不要问"要不要支持批量"。
- 上传区域整块作为 drop zone，配合明显的 hover / dragover 视觉反馈；单条项目可单独重试或移除。
- 处理并发要限制（避免打满上游速率），最好顺序或小并发（≤ 3）处理。
- 单文件大小、总张数上限要在 UI 里就写清楚，超限直接跳过并 toast 提示具体原因，不要静默丢。

实现细节（踩过坑后的最佳实践）：
- 隐藏的 `<input type="file">` 用 `className="sr-only"` 而不是 `hidden`/`display:none` —— 后者在部分浏览器上 `inputRef.current.click()` 会被静默拦截，造成"选择文件"按钮看似没反应。
- Drop zone 外层 div 同时担当"点击弹选择器"时，内部按钮不要用 `stopPropagation` 拦住冒泡，而是在外层 onClick 里用 `target.closest("button")` 判断、只在非按钮区域才弹选择器，否则会让按钮本身看起来也没反应。
- `multiple` 属性必需写在 `<input>` 上；对话框弹出后用户需要 Ctrl / ⌘ 多选 —— 提示文案里写清楚，避免用户以为只能一张。
- `handleInput` 里先把 `event.target.files` 取完再重置 `event.target.value = ""`，避免后续选相同文件不触发 change。
