# 项目正在向度小满申报：能力版图与对接诉求

财务 X 光（FinSight）正在向 **度小满**（Du Xiaoman，原百度金融）提交项目申报材料，题目包含"技术资源组合方案""项目完成度""若度小满投入资源希望获得什么支持"等。

**Why**：这决定了对外叙事的落点——材料要讲"我们和度小满的能力互补"，而不是单纯讲产品好。也意味着后续做功能优先级时，能与度小满理财形成互补的能力（跨平台全景资产 Context）比纯自娱的功能更有价值。

## 度小满真实能力版图（2026-07 核实）

- **牌照**：基金销售牌照（北京度小满基金销售有限公司，2018 年获批，当年证监会仅发两张）、第三方支付、小贷、保险经纪、消费金融（持股哈银消金 30%）。
- **C 端产品**：度小满理财（一站式基金投资，与持牌机构合作甄选公募基金 / 集合资管计划）、小满信贷（有钱花）、度小满支付。
- **金融大模型「轩辕」**：国内首个千亿级中文金融大模型（基于 1760 亿参数 Bloom 训练），后开源 6B / 13B / 70B 共 12 款；2024 年末开源**国内首个金融推理大模型「轩辕-FinX1」**，采用"思维链 + 过程奖励 + 强化学习"，可展示完整思考过程（可解释 AI 方向）。
- **金科开放平台**：云帆开放平台 2.0、磐石一站式金科平台（智能获客、大数据风控、身份识别、反欺诈、风险监测）、ABS 云平台、区块链 BaaS 平台；已与上百家银行 / 金融机构合作，理念是"伙伴先赢，持续共赢"。
- **风控积累**：智能化征信解读中台（NLP + 图计算，把征信报告解读成 40 万维风险变量，信贷风险降低 25%）。

## 我方缺口 → 度小满资源的映射（材料的核心论证）

| 我方缺口（真实存在，见其它 memory） | 对应度小满资源 |
|---|---|
| 基金穿透只能拿到季度前十大重仓，覆盖约 60-70%，剩下是结构性盲区 | 基金销售牌照体系内的完整持仓 / 定期报告结构化数据 |
| 行情桥接靠本机 Python + 内网穿透隧道，双数据源均无 SLA（见 `project_quote_backend.md`） | 云帆 / 磐石开放平台的机构级行情与基金数据接口 |
| 用通用视觉 / 推理模型 + 提示词工程，缺金融领域语义 | 轩辕系列，尤其 FinX1 的可展示思考链——正好匹配"诊断过程必须可解释"的产品定位 |
| 风控阈值（单票 >15%、应急金 <3 个月）是自定经验值 | 度小满风控方法论 + 征信解读中台的多维风险变量经验 |
| 无投顾资质，功能被迫收窄在"诊断不建议" | 持牌资质 + 合规团队，可在合规框架内把诊断向配置建议延伸一步 |
| OCR 只在有限机构截图上验证过 | 脱敏的多机构账单截图样本 + 真实用户测试场景 |

## 我方能带给度小满的价值（反向论证，别漏）

度小满理财只能看到用户在自家买的产品，看不到用户散在银行 / 券商 / 其它平台的资产。财务 X 光提供的是**跨平台全景资产 Context + 穿透后的真实敞口**，是度小满理财缺的那块拼图；同时也是轩辕大模型在 **C 端个人财富诊断**场景的落地案例（目前轩辕主要用在营销 / 客服 / 风控 / 办公 / 研发，C 端诊断类应用是空白）。

## How to apply

- 再被问到申报材料类问题（完成度、技术方案、资源诉求、商业模式），先读这条，保持对外叙事一致，别每次重新编一套说法。
- 讲"最大挑战"时坚持三条实话：基金披露的数据天花板、行情桥接的运维负债、让模型不越界比让它能说难得多。这三条已经在 `project_quote_backend.md` 与 `feedback_xray_no_industry.md` 里有事实支撑，不要临时发明新的挑战。
- 提资源诉求时必须对上度小满真实有的东西（上表），不要泛泛要钱要人——这是材料能不能打动评审的关键。
