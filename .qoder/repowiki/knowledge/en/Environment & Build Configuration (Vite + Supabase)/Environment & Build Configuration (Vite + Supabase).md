This project uses a straightforward, file-based configuration approach with no centralized config loader. Configuration is split across three layers:

**1. Vite build-time configuration**
- `vite.config.ts` defines the React plugin, dependency optimization (`lucide-react`, `framer-motion`, `recharts`), manual chunking for vendor/ui bundles, and the `@` path alias pointing to `./src`. No environment-specific configs are used — all runtime secrets are injected via Vite's `import.meta.env`.
- `components.json` configures shadcn/ui (style: new-york, tsx, CSS variables, aliases for `@/components`, `@/lib`, `@/hooks`).
- `tailwind.config.js` and `postcss.config.js` handle styling pipeline setup.

**2. Frontend runtime env vars (Vite)**
- Supabase credentials are consumed through `import.meta.env.VITE_SUPABASE_URL` and `import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY` in `src/integrations/supabase/client.ts` and `src/services/chatService.ts`.
- These must be provided at build time via `.env` files (not present in the repo). There is no validation or default fallback logic — missing values will cause runtime errors.

**3. Supabase Edge Functions configuration**
- `supabase/config.toml` declares each function and sets `verify_jwt = true` for most endpoints, except `read-shared-report` which allows anonymous access.
- Secrets inside functions are read via `Deno.env.get()` — expected keys include `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, and `SUPERUN_API_KEY`.
- The Supabase project ID is set to `bv0atyuqnuwjoaxr70wz`.

**4. Session metadata**
- `.sxq/config.json` stores AI session state (sessionId, timestamps, owner info) — this is generated by the UX Arts tooling and not part of application configuration.

**Conventions & rules observed:**
- All secrets follow the `VITE_*` prefix for frontend and plain names for Deno functions.
- No config schema validation exists; values are assumed to be strings.
- Environment separation is implicit (build-time vs runtime) rather than explicit via separate `.env.development` / `.env.production` files.
- The Supabase client is created once and exported from `src/integrations/supabase/client.ts` — consumers should import this singleton rather than creating their own instances.
